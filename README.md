# ストップウォッチ PWA

iPhoneのホーム画面に追加できる、オフライン対応のストップウォッチです。

- 開始・停止・再開・リセット
- 開始と同時にラップ1を表示し、計測中の累積時間とラップタイムを更新
- ラップタイムと累積時間、最速・最遅ラップの色分け
- 停止中のラップ一覧をPNG画像に保存（100ラップごとに分割）
- 初回オンライン読み込み後のオフライン起動
- 経過時間とラップの端末内保存、再起動時の復元
- iPhoneのノッチとホームインジケーター用余白、専用アイコン

ビルドやnpm installは不要です。外部ライブラリー、外部フォント、通信サーバーを使いません。元のダウンロードフォルダーのHTMLは変更していません。

## GitHub Pagesで公開する

1. GitHubで新しいリポジトリを作成します。例：`stopwatch-pwa`。無料アカウントで進める場合は **Public** を選びます。公開されたソースコードは誰でも閲覧できます。
2. ZIPを展開します。展開したフォルダーの**中身**をアップロードします。ZIPそのものはアップロードしません。
3. リポジトリ画面で **Add file → Upload files**（空のリポジトリでは **uploading an existing file**）を開きます。
4. 展開したフォルダーの中身をすべてアップロードして、**Commit changes** を押します。`controller.js`、`storage.js`、`view.js`、`lap-list.js`、`lap-image.js`、`lap-export.js`、`export-preview.js` も動作に必要です。
5. リポジトリのトップで `index.html` が見えることを確認します。`stopwatch-pwa/index.html` のように一段深い場所に入れないでください。
6. **Settings → Pages → Build and deployment** を開きます。
7. **Source: Deploy from a branch**、**Branch: main**、**Folder: / (root)** を選び、**Save** を押します。既定ブランチが別名ならそのブランチを選びます。
8. 数分待ち、Pages画面の **Visit site** を開きます。公開URLは通常 `https://ユーザー名.github.io/リポジトリ名/` です。

GitHubのファイル表示URL（`github.com/.../blob/...`）ではなく、**Pagesの公開URL**をiPhoneで開いてください。HTTPSで公開されます。GitHub Actionsの設定は不要です。

公式手順：[GitHub Pagesサイトを作成する](https://docs.github.com/ja/pages/getting-started-with-github-pages/creating-a-github-pages-site)

## iPhoneに追加する

1. iPhoneの **Safari** でPagesの公開URLを開きます。
2. 初回はオンラインのまま数秒待ち、ファイルの保存を完了させます。
3. Safariの共有メニューを開き、**ホーム画面に追加**を選びます。iOSによっては「その他」から共有を開きます。
4. **Webアプリとして開く**のスイッチが表示される場合はオンにして、**追加**を押します。
5. ホーム画面にできたアイコンから起動します。

「ホーム画面に追加」が見つからない場合は、共有メニューの「アクションを編集」で追加します。

公式手順：[iPhoneのSafariでウェブサイトをアプリにする](https://support.apple.com/ja-jp/guide/iphone/iphea86e5236/ios)

## 公開後の確認

1. 「開始」を押すとすぐに「ラップ1」が現れ、累積時間とラップタイムが進むことを確認します。「ラップ」を押すと、その行が確定し、ラップ2が0秒から進みます。「停止」で計測中のラップも止まり、「開始」で同じラップの続きから再開します。
2. ホーム画面へ戻ってからアプリを開き直し、記録が残ることを確認します。
3. 計測中に画面をロックし、少し待って解除します。ロックしていた時間を含めて表示が進むことを確認します。
4. 一度オンラインで起動した後、アプリを閉じ、機内モードでホーム画面のアイコンから起動します。

計測は開始時刻との差から計算するため、画面が閉じている間も経過時間を復元できます。端末の日時を手動で変更すると計測に影響します。ブラウザーのサイトデータを削除した場合やOSが保存領域を消去した場合、記録やオフライン用データは失われます。記録は端末内に保存し、機器間では同期しません。

## ラップ一覧を画像で保存する

1. 計測後に **停止** を押します。左上の小さなグレーの保存アイコンが押せるようになります。文字・背景・枠は付けていません。
2. 保存アイコンを押し、作成された画像をプレビューで確認します。
3. **共有・保存** を押して、iPhoneの共有メニューから保存先を選びます。「画像を保存」がある場合は写真に保存できます。保存先の表示は端末やOSにより異なります。
4. 共有に失敗した場合は、もう一度 **共有・保存** を押します。ファイル共有に対応していない端末では、プレビュー画像の長押しから保存できる場合があります。各画像の下に個別のダウンロードリンクは表示しません。
5. **閉じる** で元の画面に戻ります。画像保存は計測値やラップ記録を変更しません。共有をキャンセルしてもプレビューは残ります。

黒背景の画像に、計測した時間の数字と「ラップ・累積時間・ラップタイム」の一覧を載せます。上部の「経過時間」という文字は表示しません。画面外の行と停止時の最後の未確定ラップも含みます。操作ボタン・スクロールバー・日時は画像に入りません。1枚に最大100ラップを収め、101ラップなら2枚、230ラップなら3枚になります。時刻の数字と列の見出しは各画像に載せ、最速・最遅は全確定ラップを通して判定します。

PNGは通常横幅1170pxで作成し、メモリー不足などで作成できない場合は430pxで再試行します。文字・行・余白は同じ比率で拡大し、縦幅はラップ数に合わせて整数ピクセルに丸めます。端末内で処理するので、オフラインでも画像を作成できます。写真への保存結果まではアプリから確認できないため、「保存完了」の表示は出しません。

## 更新する

計測・保存・画面描画・操作の連携を別ファイルに分離した構成です。保存キーとデータ形式は同じなので、公開URLが同じなら以前の計測記録を引き継ぎます。

最新版（1.2.4）では、画像の内容・描画とPNGファイルへの変換を別ファイルに分離し、プレビューごとに生成・共有・画像用URLをまとめて管理する構成に整理しました。閉じたプレビューの処理が後から完了しても、次のプレビューを変更しません。PNGの横幅1170px、100ラップごとの分割、画面の配置・計測・保存形式は維持しています。キャッシュのバージョンは `v15` に更新済みです。

開始と同時にラップ1を表示する動作、ラップを押したときの確定と次のラップの開始、停止・再開、計測中ラップの復元は維持しています。最速・最遅の色分けは引き続き確定済みのラップだけを対象にします。

横線は元の幅のまま、スクロールバーの位置を右側へ12px離す配置を維持しています。移動量は `styles.css` の `--scrollbar-offset` で調整できます。保存アイコンは絶対配置のため、時刻・既存ボタン・一覧の配置を押し下げません。保存キーとデータの形式は前の版と同じです。

### 公開済みのサイトを更新する手順

1. 最新の `stopwatch-pwa.zip` を右クリックし、**すべて展開**を選びます。
2. GitHubでストップウォッチのリポジトリを開き、**Code → Add file → Upload files** を押します。
3. 展開したフォルダーを開き、**中のファイルとフォルダーをすべて**アップロード欄へドラッグします。`index.html` がリポジトリのトップに配置されるようにします。同じ場所の同じ名前のファイルは上書きされます。
4. コミットメッセージに `Refactor lap image rendering and preview lifecycle` と入力し、**Commit directly to the main branch** を選んで **Commit changes** を押します。確認画面が表示された場合は、再度 **Commit changes** を押します。
5. GitHub Pagesへの反映を待ち、オンラインで一度アプリを開いて新しい版を準備します。このアプリを開いているSafariタブとホーム画面のアプリをすべて閉じてから、開き直します。

新しく追加した `lap-image.js`、画像生成の `lap-export.js`、プレビューの `export-preview.js` も必要なので、ZIPに入っている一式を同じコミットでアップロードしてください。ZIP自体をGitHubに置くだけでは更新されません。既に公開済みならPagesの設定はそのまま使えます。

### 次回以降のコード更新

変更したファイルと、バージョンを上げた `sw.js` を同じコミットでアップロードします。

```js
const CACHE_NAME = `${CACHE_PREFIX}v16`;
```

オンラインでアプリを開くと新しい版を準備します。開いている計測画面を強制更新しない設計なので、更新後はこのアプリを開いているSafariタブとホーム画面のアプリをすべて閉じてから開き直してください。ファイルを追加した場合は `sw.js` の `ASSETS` にも追加します。

## コードの構成

| ファイル | 役割 |
| --- | --- |
| `app.js` | 各部品の初期化とService Workerの登録 |
| `stopwatch.js` | 計測、計測中ラップの算出、保存データの検証、時間の整形、ラップの比較 |
| `storage.js` | 端末内への保存と読み込み、保存失敗時の処理 |
| `view.js` | 時刻・ボタンの描画、ラップ一覧との連携、時刻の文字幅調整 |
| `lap-list.js` | 確定行と計測中行の描画、行の再利用、色分けと見出しの管理 |
| `lap-image.js` | 記録のコピー、100行単位の分割、画像の文字・色・配置の描画 |
| `lap-export.js` | CanvasのPNG変換、低解像度での再試行、ファイル名・進捗・中止の管理 |
| `export-preview.js` | プレビュー単位の生成・共有の管理、端末への受け渡し、画像用URLの解放 |
| `controller.js` | ボタン操作、画面復帰、描画ループ、保存の連携 |
| `sw.js` | アプリ一式のオフラインキャッシュと旧版の整理 |
| `styles.css` | レイアウトと外観 |

描画ループは起動・操作・画面復帰で同じ経路から管理します。イベントの登録時に解除処理もまとめ、終了時に取りこぼさず解除できる構成にしています。終了後に残ったコールバックが呼ばれた場合も、計測や描画を再開しません。ビルドと依存パッケージは引き続き不要です。

`stopwatch.laps` と `recordLap()` の戻り値は変更不可です。ラップの追加は `recordLap()`、消去は `reset()` を通じて行います。ラップ一覧の参照は追加・リセット時だけ変わるので、画面側で不要な行更新を省けます。`snapshot()` は保存用の独立したコピーを返し、保存キーとJSONのバージョンは従来のままです。

`stopwatch.laps` は確定済みのラップです。`currentLap()` は現在の経過時間と直前の確定ラップから計測中のラップを算出し、リセット直後は `null` を返します。描画時は同じ経過時間からメイン表示と計測中ラップを算出します。計測中のラップを別途保存する必要はなく、従来の保存データから停止・計測状態を含めて復元できます。

`read()` は画面用に `{ status, elapsed, laps, currentLap }` を返します。計測中の時刻取得は1回で、メイン表示とラップの値がそろいます。画面全体の更新と時刻だけの更新は、この同じ形式のデータを使います。保存用データは従来どおり `snapshot()` で取得します。

## ローカルで確認する

HTMLのダブルクリック（`file://`）ではPWAとして動作しません。Pythonがあれば、このフォルダーで次を実行します。

```powershell
python -m http.server 8000 --bind 127.0.0.1
```

ブラウザーで `http://127.0.0.1:8000/` を開きます。このURLはPC内の確認用です。iPhoneではGitHub PagesのHTTPS URLを使います。

Node.jsがある場合は `npm test` または `node --test tests/*.test.js` で、計測・保存復元・オフラインキャッシュのテストを実行できます。依存パッケージのインストールは不要です。

更新後に自動テスト73件を確認しています。既存の計測・保存復元・互換性・描画・オフラインキャッシュに加え、1・100・101・230ラップの分割、全体を通した色分け、低解像度での再試行、生成失敗、共有非対応・キャンセル、プレビューを閉じた後の処理、画像用メモリーの解放を対象にしています。画像保存が停止中に限られ、計測値の取得が一度だけで、計測記録を変更せず保存処理も追加しないことを確認しています。画像に「経過時間」の文字が含まれないこと、表示途中の失敗時の解放と再試行、古い処理の進捗表示の抑止、共有の二重起動防止も確認しています。

描画処理の自動テストはテスト用DOMとCanvasを使い、ブラウザー固有の表示や写真アプリへの保存は再現しません。iPhone実機での共有・写真保存の最終確認は未実施です。

1.2.0ではPCのブラウザーで、1・100・101・230ラップの画像生成と分割、PNGの表示、実際のダウンロードを確認しています。100行のPNGは860×9152px、1行は860×440px、30行は860×2992pxです。320×568pxの画面では、保存アイコンが18px、操作範囲が44px四方で、時刻表示と重ならず横にはみ出さないことを確認しています。プレビューをEscで閉じると保存ボタンにフォーカスが戻り、記録が維持されることも確認しています。

1.2.1では、同じCanvas描画処理を使って1・3・100・101・230ラップのPNGを生成し、変更前後の計8枚を画素単位で比較しました。画像の差は上部の「経過時間」という文字の領域だけで、それ以外の画素と画像寸法は一致しています。計測・保存・通常画面のHTMLとCSSは1.2.0と同じです。この版のブラウザー操作とiPhone実機での確認は未実施です。

1.2.2では自動テスト70件で、プレビューにダウンロードリンクがなく、画像をまとめて共有できること、共有非対応時は画像を残して長押しを案内すること、共有失敗後に再試行できることを確認しています。画像生成と計測処理は1.2.1と同じです。この版のブラウザー操作とiPhone実機での確認は未実施です。

1.2.3では自動テスト70件に加え、実際のCanvas描画処理で1・3・100・101・230ラップの計8枚のPNGを生成し、すべて横幅1170pxで背景が不透明であることを確認しました。1行の画像は1170×599px、3行は1170×838px、30行は1170×4071px、100行は1170×12451pxです。メモリー不足時の430pxへの再試行も自動テストで確認しています。この版のブラウザー操作とiPhone実機での確認は未実施です。

1.2.4では自動テスト73件に加え、実際のCanvas描画処理で1・3・100・101・230ラップの計8枚を変更前後で生成し、寸法・RGB・透明度がすべて一致することを確認しました。新しいテストでは、遅れて届くcloseイベント、前のプレビューで開始した共有の失敗、画像生成中の終了処理が新しいプレビューを変更しないことを確認しています。追加した描画モジュールもオフライン対象です。計測・保存・通常画面のHTMLとCSSは1.2.3と同じです。この版のブラウザー操作とiPhone実機での共有・写真保存の確認は未実施です。
