# ストップウォッチ PWA

元のHTMLの見た目と操作を保った、iPhoneのホーム画面に追加できるストップウォッチです。

- 開始・停止・再開・リセット
- ラップタイムと累積時間、最速・最遅ラップの色分け
- 初回オンライン読み込み後のオフライン起動
- 経過時間とラップの端末内保存、再起動時の復元
- iPhoneのノッチとホームインジケーター用余白、専用アイコン

ビルドやnpm installは不要です。外部ライブラリー、外部フォント、通信サーバーを使いません。元のダウンロードフォルダーのHTMLは変更していません。

## GitHub Pagesで公開する

1. GitHubで新しいリポジトリを作成します。例：`stopwatch-pwa`。無料アカウントで進める場合は **Public** を選びます。公開されたソースコードは誰でも閲覧できます。
2. ZIPを展開します。展開したフォルダーの**中身**をアップロードします。ZIPそのものはアップロードしません。
3. リポジトリ画面で **Add file → Upload files**（空のリポジトリでは **uploading an existing file**）を開きます。
4. 展開したフォルダーの中身をすべてアップロードして、**Commit changes** を押します。`controller.js`、`storage.js`、`view.js` も動作に必要です。
5. リポジトリのトップで `index.html` が見えることを確認します。`stopwatch-pwa/index.html` のように一段深い場所に入れないでください。
6. **Settings → Pages → Build and deployment** を開きます。
7. **Source: Deploy from a branch**、**Branch: main**、**Folder: / (root)** を選び、**Save** を押します。既定ブランチが別名ならそのブランチを選びます。
8. 数分待ち、Pages画面の **Visit site** を開きます。公開URLは通常 `https://ユーザー名.github.io/リポジトリ名/` です。

GitHubのファイル表示URL（`github.com/.../blob/...`）ではなく、**Pagesの公開URL**をiPhoneで開いてください。HTTPSで公開されます。GitHub Actionsの設定は不要です。

公式手順：[GitHub Pagesサイトを作成する](https://docs.github.com/ja/pages/getting-started-with-github-pages/creating-a-github-pages-site)

## iPhoneに追加する

1. iPhoneの **Safari** でPagesの公開URLを開きます。
2. 初回はオンラインのまま数秒待ち、ファイルの保存を完了させます。
3. Safariの共有メニューを開き、**ホーム画面に追加**を選びます。iOSによっては「その他」から共有を開きます。
4. **Webアプリとして開く**のスイッチが表示される場合はオンにして、**追加**を押します。
5. ホーム画面にできたアイコンから起動します。

「ホーム画面に追加」が見つからない場合は、共有メニューの「アクションを編集」で追加します。

公式手順：[iPhoneのSafariでウェブサイトをアプリにする](https://support.apple.com/ja-jp/guide/iphone/iphea86e5236/ios)

## 公開後の確認

1. 「開始」→「ラップ」→「停止」と操作し、経過時間・累積時間・ラップを確認します。
2. ホーム画面へ戻ってからアプリを開き直し、記録が残ることを確認します。
3. 計測中に画面をロックし、少し待って解除します。ロックしていた時間を含めて表示が進むことを確認します。
4. 一度オンラインで起動した後、アプリを閉じ、機内モードでホーム画面のアイコンから起動します。

計測は開始時刻との差から計算するため、画面が閉じている間も経過時間を復元できます。端末の日時を手動で変更すると計測に影響します。ブラウザーのサイトデータを削除した場合やOSが保存領域を消去した場合、記録やオフライン用データは失われます。記録は端末内に保存し、機器間では同期しません。

## 更新する

今回のリファクタリング版は、計測・保存・画面描画・操作の連携を別ファイルに分離しています。保存キーとデータ形式は同じなので、公開URLが同じなら以前の計測記録を引き継ぎます。ラップ一覧の右端に設けた12pxの余白もそのままです。キャッシュのバージョンは `v3` に更新済みです。

### 公開済みのサイトを更新する手順

1. 最新の `stopwatch-pwa.zip` を右クリックし、**すべて展開**を選びます。
2. GitHubでストップウォッチのリポジトリを開き、**Code → Add file → Upload files** を押します。
3. 展開したフォルダーを開き、**中のファイルとフォルダーをすべて**アップロード欄へドラッグします。`index.html` がリポジトリのトップに配置されるようにします。同じ場所の同じ名前のファイルは上書きされます。
4. コミットメッセージに `Refactor stopwatch app` と入力し、**Commit directly to the main branch** を選んで **Commit changes** を押します。確認画面が表示された場合は、再度 **Commit changes** を押します。
5. GitHub Pagesへの反映を待ち、オンラインで一度アプリを開いて新しい版を準備します。このアプリを開いているSafariタブとホーム画面のアプリをすべて閉じてから、開き直します。

この版では追加のJavaScriptファイルが必要なため、ZIPに入っている一式を同じコミットでアップロードしてください。既に公開済みならPagesの設定はそのまま使えます。

### 次回以降のコード更新

変更したファイルと、バージョンを上げた `sw.js` を同じコミットでアップロードします。

```js
const CACHE_NAME = `${CACHE_PREFIX}v4`;
```

オンラインでアプリを開くと新しい版を準備します。開いている計測画面を強制更新しない設計なので、更新後はこのアプリを開いているSafariタブとホーム画面のアプリをすべて閉じてから開き直してください。ファイルを追加した場合は `sw.js` の `ASSETS` にも追加します。

## コードの構成

| ファイル | 役割 |
| --- | --- |
| `app.js` | 各部品の初期化とService Workerの登録 |
| `stopwatch.js` | 計測、保存データの検証、時間の整形、ラップの比較 |
| `storage.js` | 端末内への保存と読み込み、保存失敗時の処理 |
| `view.js` | 時刻・ボタン・ラップの描画、時刻の文字幅調整 |
| `controller.js` | ボタン操作、画面復帰、描画ループ、保存の連携 |
| `sw.js` | アプリ一式のオフラインキャッシュと旧版の整理 |
| `styles.css` | レイアウトと外観 |

描画ループは起動・操作・画面復帰で同じ経路から管理します。イベントや画面サイズの監視は終了処理で解除できる構成にしています。ビルドと依存パッケージは引き続き不要です。

## ローカルで確認する

HTMLのダブルクリック（`file://`）ではPWAとして動作しません。Pythonがあれば、このフォルダーで次を実行します。

```powershell
python -m http.server 8000 --bind 127.0.0.1
```

ブラウザーで `http://127.0.0.1:8000/` を開きます。このURLはPC内の確認用です。iPhoneではGitHub PagesのHTTPS URLを使います。

Node.jsがある場合は `npm test` または `node --test tests/*.test.js` で、計測・保存復元・オフラインキャッシュのテストを実行できます。依存パッケージのインストールは不要です。

リファクタリング後に自動テスト23件とJavaScriptの構文を確認しています。計測・保存復元・以前の保存データとの互換性・ストレージが使えない場合・画面復帰時の描画ループ・ラップの色分け・オフラインキャッシュを対象にしています。この実行環境ではローカルサーバーに接続できなかったため、ブラウザーの表示とiPhone実機での最終確認は未実施です。
